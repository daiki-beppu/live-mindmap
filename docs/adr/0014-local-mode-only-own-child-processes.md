# ローカルモードで選べる差分更新のモデルは、live-mindmap が起動する子プロセスだけにする

ローカルモードが約束するのは、会議の中身（音声・発言・マップ・共有画面と、そこから作るもの）が Mac の外に出ないことである。この約束は、live-mindmap が自分で検証できる範囲にだけ張る。そのため、ローカルモードで選べる差分更新のモデルは、サーバーが起動する子プロセス（Apple Intelligence・内蔵、ADR 0012）に限る。Ollama・LM Studio・利用者が自分で立てた llama.cpp などの外部の実行環境は、ループバックで動いていても、通常のモードでしか選べない（[#382](https://github.com/daiki-beppu/live-mindmap/issues/382)）。

## Considered Options

- **宛先がループバックなら、外部の実行環境も許す**: 当初はこの形で考えていた。しかし Ollama は、`:cloud` の付いたモデル名を受けると、宛先が localhost のままでも ollama.com で推論する（[#375](https://github.com/daiki-beppu/live-mindmap/issues/375)）。宛先を検査しても、ループバックの裏で中身が外に出ることは見抜けない。既知の抜け道を名前で拒んでも、その先は実行環境の作りしだいになる
- **外部の実行環境を、ローカルモードとは別の名前で許す**: 区別はつく。しかし規程で外部の AI を禁じられている人には、約束の無い選択肢は使えない。名前を 2 つに分けても、選べる道は増えない
- **LAN 内の自前のサーバーも「ローカル」に含める**: LAN の機械に送った時点で、中身は Mac の外に出ている。定義と食い違う

## Consequences

- セッションの開始時に検査するのは、宛先の URL ではなく、差分更新のモデルの種類（自前の子プロセスか）と、宛先がその子のループバックのポートであることになる。違えば開始を拒む
- ローカルモードでは、Claude の呼び出し（Agent SDK）を読み込まない。このため、Claude Code 本体のテレメトリーはローカルモードでは出ていかない
- 大きなモデルを使いたい利用者（32GB 以上の段など）には、内蔵の子プロセスで別の GGUF を明示の pull で読ませることで応える。外部の実行環境を許すことでは応えない
- 約束に含めないのは、会議の中身を含まない通信である（SpeechAnalyzer の日本語モデルの初回の取得、内蔵のモデルの明示の pull）。README では、これらを名前を挙げて書く
