# Haiku 5.5 の effort を low と high にして cli eval にかける（issue #654）

2026-10-09 に、16GB の M4 で計測した。使い捨てのブランチで、main には入れない。

## 条件

- 「Haiku 5.5 と Sonnet 5.5 を同じ素材で cli eval にかける」（#614）と同じにした。替えたのは `LM_EVAL_EFFORT` だけ
  - コードは #614 と同じ版（`5bf0454`）に、同じ評価用のパッチ（[../haiku-eval/eval-only.patch](../haiku-eval/eval-only.patch)）を当てた。main は #614 の後に SYSTEM が変わった（#652、共有画面を指す発言の書き方）ので、main で流すと effort 以外の差が混ざる。そのため main ではなく #614 の版で流した
  - 素材は `synth/screen` と `synth/facilitators`。認証は Claude Code のサブスク（`env -u ANTHROPIC_API_KEY`）。料金・遅れ・反映までの遅れの数え方は #614 と同じ（[../haiku-eval/cost.mjs](../haiku-eval/cost.mjs)・[../haiku-eval/lagReal.mjs](../haiku-eval/lagReal.mjs)）。流し方は [run.sh](run.sh)
  - medium の値と Sonnet 5.5 の値は、#614 のものをそのまま使った
- 進め方: まず `synth/screen` を low・high で 1 本ずつ流した。high は 1 回の秒数で見込みがなかったので切った。low は screen・facilitators を 2 本ずつと、screen を等速（`--realtime`）で 1 本流した
- 基準（#615 で決めた）: 決定・TODO の再現率が Sonnet 5.5 から落ちないこと（2 本ずつで、差は 1 件まで）、かつ等速の screen で反映までの遅れの p90 が 12 秒以内

## 分かったこと

1. **low は遅れの基準に届く。品質の下限には届かない。** 等速の p90 は 8.3 秒で、Sonnet（8.0 秒）とほぼ同じ。品質は、screen の TODO が 2 本とも 4/7 で、Sonnet の 5/7・6/7 から 1〜2 件落ちた（2 本の合計で 8 対 11）。screen の決定も 2 本とも 1 件少ない（3/5 対 4/5）。facilitators は、決定も TODO も Sonnet と合計で並んだ（決定 3 対 3、TODO 6 対 6）。等速の 1 本は決定 3/5 対 4/5、TODO 5/7 対 5/7
2. **high は見込みがない。** thinking が medium の約 2 倍（120.0k）、1 回の中央は 16.0 秒、最大 52.3 秒で、待ち時間なしの medium（10.3 秒）より 1.5 倍遅い。等速の p90 は、medium ですでに 11.5 秒あるので、12 秒に収まらない。品質も、決定は 2/5 で上がらなかった（TODO は 6/7）。入力も最大 98.1k まで行き、10 万トークンに近づいた
3. **low は、medium より悪くない。** 決定・TODO の合計（screen と facilitators の 2 本ずつ）は、low 23 対 medium 21（Sonnet は 28）。screen の TODO は medium のほうが良いが、facilitators の TODO と screen の決定は low のほうが良い。捨てた操作も減った（screen で 20・29 → 14・21）。thinking は約半分（26k 前後）、1 回の中央は screen で 10 秒台から 6〜7 秒台に下がった
4. **料金は 1 会議 $0.05〜0.08。** Sonnet の約 1/11〜1/14。等速の screen で $0.078（Sonnet $0.892 の約 1/11）
5. **Haiku の弱いところは screen に集まる。** 画面のある会議で、決定・TODO を 1 件ずつ落とし、捨てた操作が Sonnet の数倍ある。facilitators（画面なし）では差がない
6. どの effort でも、失敗・不正な出力・10 万トークン超は 0
