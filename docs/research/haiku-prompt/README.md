## 分かったこと

1. **追記では下限に届かない。** v2 の 2 本の合計は、決定 7 対 Sonnet 6（並ぶ）、TODO 9 対 12（3 件少ない）。1 本目は Sonnet を上回ったが、2 本目は追記なしより悪い。v1 も TODO は 4/7 のまま
2. **品質の上下は、捨てた操作の数で決まっている。** Haiku が落とした TODO・決定（野々村の 2 件の TODO など）は、作ろうとした操作が「親が存在しない」で捨てられたもの。捨てた操作の大半は、**前の応答で付けた仮 id を親に書いた**もの（Sonnet も facilitators では同じ間違いを 12 件している、#614）
3. **捨てられると連鎖する。** 変更（`renderChanges`）はマップ同士の差なので、捨てた操作は出てこない。モデルは自分の足したノードがあるつもりで、その仮 id の下に次の応答でも足し続ける。v1 では 1 つの捨てから 14 回目まで毎回 2〜4 件捨て続けた。15 回目に開き直してマップの全体を送り直すと止まる
4. **仮 id を念押しすると、かえって増える。** v1（「n の id で指す」）で 8 → 38 件、v2（「追加に出ていなければ作られていない」）でも 14・35 件。プロンプトの文では、モデルは変更の行と自分の操作を突き合わせない
5. **決定の念押しは半分だけ効いた。** 「大学前の店長に入ってもらう」を TODO だけにする崩れ方は、v1 と v2 の 1 本目では出ず、v2 の 2 本目では出た（追記なしでは #654 の待ち時間なしの 2 本と今回の 1 本の全部で出た）。v2 の 2 本目は、ほかに決定の本文から店の名前（北口・川沿い）を落として外れた
6. **main の SYSTEM（#652）で Sonnet の指す発言は 4/20 → 12〜14/20 に上がったが、Haiku は 5〜9/20 にとどまる。** 下限の判定には入れていないが、画面を指す発言の読み解きでも差がある
7. 遅れ: 追記で thinking が 25k → 31〜35k に増え、1 回の中央は 7.0 → 7.3〜8.7 秒。料金は 1 会議 $0.06 前後（Sonnet の約 1/11）
