# AEC3 の開始直後の設定の計測（Issue #119）

Issue #118（`2026-10-03-aec-startup-double-talk.md`）で、漏れの無い条件（イヤホン相当）の開始直後に、発話が定常より余計に削られると分かった。AEC3 の設定を変えて、これを小さくできるかを `stt-bench echo` で測った。結論は次のとおり。実会議の録音は使っていない。各条件 1 回の計測（繰り返しのばらつきは測っていない。計測は決定的で、同じ設定で再実行すると同じ値になった）。

- **本番の設定を変えた。** エコー経路の強さの初期値（`ep_strength.default_gain`）を 1（既定）から 0.01 に下げた。変更はこの 1 項目だけ（他は AEC3 の既定値のまま）。
- **漏れ無しの開始 1・2・3・5 秒の発話の残り方は、同じ実行の 30 秒・60 秒との差が 1.0 dB 以内になった**（基準は 3 dB 未満。変更前は 2 秒で 9.1 / 9.4 dB 小さかった）。
- **漏れ −10 dB の遅れ 40 / 200 / 300 ms × 5 / 30 / 60 秒の 9 セルは、発話の残り方も漏れの低下量も、変更前（#118 の表）と同じ値**（差 0.00 dB。9 セル × 2 指標）。
- 悪化する範囲（受入条件の外、参考）: 漏れ −10 dB・開始 1〜2 秒では漏れの低下量が下がった（下の表）。発話の残り方は、1 秒では変更前より多く残り、2 秒以降は変わらないか同じ。

## 測り方

- 道具: `helper/Sources/stt-bench echo`（手順は `helper/README.md`）。台本・音声は #118 と同じ（`helper/bench/scenarios/echo.json` を `stt-bench synth` で再生成し、`meeting.wav` と `self.wav` の md5 が #118 の音声と一致することを確認した）。音声と計測の出力は `/tmp/aec119` に置き、リポジトリには入れていない。
- 比較: `baseline`（#118 と同じ設定 = 固定コミットの AEC3 の既定値）と `production`（本番の設定）を、同じ道具・同じ音声で測った。`baseline` を再実行した値は、#118 の表（漏れ −10 dB の 9 セル、漏れ無しの 1/2/3/5/30/60 秒）と全桁で一致した。
- 漏れ無し（`--leak-gain-db -inf`）: 窓が約 11 秒あるので、`--at 1,30,60` / `2,30,60` / `3,30,60` / `5,30,60` を別々の実行にした。遅れは 200 ms（漏れ無しでは遅れによらず同じ）。比較する 30 秒・60 秒の値は、同じ実行の値。
- 漏れ −10 dB: `--leak-gain-db -10 --delays 40,200,300 --at 5,30,60`。参考の 1〜3 秒は `--at 1,30` / `2,30` / `3,30`。

```sh
cd helper
swift run -c release stt-bench echo /tmp/aec119/meeting.wav /tmp/aec119/self.wav --self-lines /tmp/aec119/self.lines.json \
  --candidate baseline,production --leak-gain-db -inf --delays 200 --at 2,30,60
```

## 結果

### 漏れ無し（発話の残り方 dB。差 = 開始 − 同じ実行の定常）

| 開始 | baseline | 30 秒との差 | 60 秒との差 | production | 30 秒との差 | 60 秒との差 |
|---|---|---|---|---|---|---|
| 1 秒 | −10.04 | −2.0 | −2.3 | −8.69 | −0.7 | −1.0 |
| 2 秒 | −14.06 | −9.1 | −9.4 | −5.37 | −0.4 | −0.7 |
| 3 秒 | −12.03 | −7.0 | −7.3 | −5.57 | −0.5 | −0.9 |
| 5 秒 | −9.77 | −4.8 | −5.3 | −5.08 | −0.1 | −0.6 |

同じ実行の 30 秒・60 秒（baseline = production）: 1 秒の実行 −8.01 / −7.71、2 秒 −4.92 / −4.64、3 秒 −5.05 / −4.70、5 秒 −4.95 / −4.52。定常の値は変わっていない（定常の残り方を下げて差を縮めてはいない）。1 秒の実行の定常が −8 dB と他より小さいのは、baseline も同じ（開始 1 秒の発話の影響が、その後の状態に残る。原因は測っていない）。

### 漏れ −10 dB（受入条件の 9 セル。発話の残り方 / 漏れの低下量 dB）

baseline と production は 9 セルすべて同じ値（差 0.00 dB）。

| 遅れ | 5 秒 | 30 秒 | 60 秒 |
|---|---|---|---|
| 40 ms | −7.6 / 38.1 | −7.7 / 36.0 | −7.6 / 32.3 |
| 200 ms | −8.2 / 38.2 | −8.1 / 39.9 | −8.2 / 33.5 |
| 300 ms | −7.8 / 31.5 | −7.2 / 29.6 | −7.5 / 37.3 |

### 漏れ −10 dB の 1〜3 秒（参考。受入条件には入っていない）

| 遅れ | 開始 | baseline 残り方 / 漏れの低下 | production 残り方 / 漏れの低下 |
|---|---|---|---|
| 40 ms | 1 秒 | −11.3 / 23.7 | −8.8 / 14.5 |
| 200 ms | 1 秒 | −8.8 / 17.3 | −7.1 / 14.3 |
| 300 ms | 1 秒 | −9.2 / 15.1 | −6.9 / 12.0 |
| 40 ms | 2 秒 | −6.8 / 17.0 | −6.8 / 14.7 |

開始 1〜2 秒の漏れの低下量は、最大 9.2 dB（40 ms・1 秒）下がった。受入条件の対象外だが、トレードオフとして記録する。

## 試した設定

探索のため、次の項目を一時的に設定の口へ通して測った。採用しなかった項目は、不要なコードを残さないため、測定後に C シムと `EchoCancellerSettings` から削除した（`production` に必要なのは `ep_strength.default_gain` だけ）。表の値を再現するには、その項目を一時的に通す必要がある。

漏れ無しの 4 か所（1/2/3/5 秒）と、漏れ −10 dB の 9 セルを、それぞれ変更前と比べた（設定は 1 項目ずつ、または組み合わせ）。`差 残り方 / 低下量` は 9 セルの最悪値（0 以上なら悪化なし）。「C1」は、漏れ無しの 4 か所すべてで、30 秒・60 秒との差が 3 dB 未満か。

| 設定（baseline からの変更） | C1 | 9 セルの最悪の差（残り方 / 低下量） |
|---|---|---|
| `delay.default_delay` = 0 / 20 / 50 / 100（既定 5） | 満たさない（2 秒で 9〜10 dB） | −0.07〜−0.36 / −4.1〜−6.7 |
| `filter.initial_state_seconds` = 0 / 5 / 10（既定 2.5） | 満たさない（2 秒で 9 dB） | −0.12〜−1.78 / −2.2〜−15.1 |
| `filter.conservative_initial_phase` = true | 満たさない（2 秒で 9.1 dB） | −0.84 / −2.2 |
| `suppressor.dominant_nearend_detection.use_during_initial_phase` = false | 満たさない | −0.28 / 0 |
| `ep_strength.default_gain` = 0.5 / 2 / 5 / 10 | 満たさない（2 秒で 8〜10 dB） | 0 / 0 |
| `ep_strength.default_gain` = 0.1 | 満たさない（2 秒 −2.9 / −3.2 で、60 秒との差が 3 dB 以上） | 0 / 0 |
| `ep_strength.default_gain` = 0.05 | 満たす（最大 2.3 dB） | 0 / 0 |
| `ep_strength.default_gain` = 0.02 | 満たす（最大 1.3 dB） | 0 / 0 |
| **`ep_strength.default_gain` = 0.01（採用）** | **満たす（最大 1.0 dB）** | **0 / 0** |
| `ep_strength.default_gain` = 0.001 / 0 | 満たす（差は ±0.6 dB 以内） | 0 / 0 |
| 0.01 + `dominant_nearend` = false / + `conservative_initial_phase` = true | 満たす | −0.28 / 0、−0.84 / −2.2（単独の 0.01 より悪い） |
| 0.02 + `initial_state_seconds` = 0 | 満たす | −0.12 / −15.1 |

- 初期の遅れの見積もり（`default_delay`）と、初期化の設定のうち `initial_state_seconds`・`conservative_initial_phase`・`dominant_nearend` は、漏れ無しの開始直後の差を縮められないか、縮めても漏れ −10 dB の 9 セルを悪化させた。
- `ep_strength.default_gain` は、開始直後の状態にだけ効き、5 秒以降の 9 セルを変えない。値が小さいほど開始直後の発話が残った。0.01 を採ったのは、基準を満たす値のうち、0.05・0.02 より差が小さく、0.001・0 のように下限に張り付かない値だから。値の根拠は、この 1 回の計測だけ。
- 外部の遅れの見積もり（`use_external_delay_estimator` と `set_stream_delay_ms`）は試していない。`default_delay` の変更だけで、(a) の効果（漏れ −10 dB の低下量が下がる）は確かめた。
- `EchoCanceller3Factory` は、固定コミットのソースに無かった。代わりに、C シムが `EchoControlFactory` を実装し、`EchoCanceller3Config` を渡した `EchoCanceller3` を作る（`helper/Sources/CWebRTCAPM/apm.cpp`）。`baseline` の設定は、この経路を通しても、AEC3 の既定の経路と同じ値になった（#118 の表を全桁で再現）。

## 受入条件との対応

| 条件 | 結果 |
|---|---|
| 漏れ無しの開始 1〜5 秒で、30・60 秒との差が 3 dB 未満 | 満たす（最大 1.0 dB） |
| 漏れ −10 dB の 9 セルで、発話の残り方と漏れの低下量が現状より悪くならない | 満たす（18 値すべて差 0.00 dB） |
| 同じ道具で変更前後の数字を比べた結果が残っている | この文書（`baseline` と `production`） |

## 測っていないこと

- 繰り返しによるばらつき（計測は決定的）、他の声・他の会議の音、遅れ 300 ms を超える条件、漏れ −10 dB 以外の漏れ（漏れ無しを除く）。
- STT の文字での比較、Bluetooth の実機。合成音声での再現だけ。
- 漏れ −10 dB の開始 1〜2 秒の漏れの低下量の悪化が、実会議で字幕にどう影響するか。
- 長い N の `bypass`（採用しない方式。今回は試していない）。
