# Lism CSS を Tailwind と比べ、Foldkit の web で使えるかの事実（Issue #771）

地図 #734 の調査チケット。web を Foldkit（`foldkit@0.167.0`・`@foldkit/ui@0.167.0`）へ載せ替えるとき、CSS の書き方を Tailwind（v4）にするか Lism CSS にするかを判断するための事実を、一次資料（公式サイトのドキュメントのソース・GitHub のソース・npm）と、捨てるブランチでの試しのビルド・ブラウザでの計測で確かめた。物差しは #747（`docs/investigations/2026-10-10-foldkit-css.md`、ブランチ `research/foldkit-css`）にそろえ、Tailwind と Foldkit の事実はそこから引く。決めるのは #772。

- **調べた「Lism CSS」:** npm の `lism-css`（公式サイト lism-css.com、GitHub `lism-css/core`、作者 ddryo、MIT・著作権表示は「Loos, Inc.」）。npm で「lism」を探すと別物が出る: `lism`（`dragmove/lism`、TypeScript の小道具集で CSS と無関係）、`lism-ui-vue`（`otusoa/lism-ui-vue`、別の作者による Vue 3 向けの実装）、`@lism-css/*`（本体の周辺パッケージ）、`@lism-ui/core`（同じ作者の旧い試し、`ddryo/lism-test`）。チケットの「Lism CSS」はパッケージの名前と説明（「Lism CSS is a layout-first CSS framework for websites.」）が一致する `lism-css` とした。
- 出典の版: `lism-css@1.0.1`（2026-10-02）、`@lism-css/plugin@0.5.1`。ソースは `github.com/lism-css/core` の `main`（コミット `ca2ab2f`、2026-10-02）。docs は同リポジトリの `apps/site/src/content/ja/`（lism-css.com のソース）。npm の数字は 2026-10-10 に `npm view` と `api.npmjs.org` で取った。
- 試しのビルド: `origin/prototype/foldkit-review` から切った手元だけの捨てるブランチ（`scratch/lism-css-try`、push していない）。Vite `8.3.2`、`vite-plugin-singlefile@2.3.3`。ブラウザでの計測は Playwright（`playwright@1.63.0`）からこの Mac の Chrome を開き、`getComputedStyle` と寸法を読んだ。
- **未検証** と書いたものは、資料を読んだだけで動かしていない、または一次資料で確かめられなかった主張。

## 結論

- **Lism CSS は「クラスと CSS 変数の CSS」で、JS の部品は任意。** 本体は約 39 KB（`main.css`）の CSS で、`l--stack`・`l--flex` などのレイアウトの部品（Every Layout 由来）と、`-p:20`・`-bgc:base` のような 1 プロパティ 1 クラス（Property Class）と、`:root` のトークン（CSS 変数）から成る。React・Astro の部品（`<Stack g="20">`）も同じパッケージにあるが、docs は CDN の `<link>` やプレーンな HTML のクラスだけで使う形を正式に載せる（README「HTML (CSS-only)」）。
- **Foldkit の `h.Class` にそのまま載り、1 ファイルの HTML に入る（検証済み）。** `h.Class("l--stack -g:5 -p:20 -bdrs:10 nopan")` は snabbdom の `{"l--stack":true,"-g:5":true,...}` になり、`:` を含む名前も壊れない。`import "lism-css/main.css"` を足して single-file で build すると、`<link>` は無く、`@layer lism-base`・`.l--stack`・`.-p\:20` が `<style>` に入った。
- **ただし、読み込むだけで今の画面の見た目が変わる（検証済み）。** `main.css` の base は全要素に `* { line-height: var(--lh, calc(1em + var(--hl) * 2)) }` を当てるので、親の `line-height` が子へ継がれなくなる。今のノード（`.map-node` に `line-height: 1.4`）を同じ文で描くと、高さが 76.8px → 96px に伸びた。見出しの太さも 700 → 600、本文の色も `#000` → `#141414` になる。`@layer lism-base { * { line-height: inherit } ... }` を後ろに足すと元の寸法に戻った（検証済み）。Tailwind の Preflight に当たるものを外す正式な口は無く、`main.css` を使う限りこの上書きが要る。
- **既定の影・角丸はトークンで消せるが、消し方は文書に無い。** `lism.config.js` の `tokens.color` で今の hex に置き換えられる（検証済み）。`tokens.bxsh: null` にすると `--bxsh--*` と `-bxsh:10`〜`50` のクラスが出なくなった（検証済み、ただし docs に載る方法ではなく、設定の深いマージの挙動に頼る）。CSS Purge（`@lism-css/plugin` の `lismCss({ purge: true })`）を使えば、使っていない `-bxsh:*`・`-bdrs:*` は出力から消える（検証済み）。
- **Purge は single-file と並べられるが、順番に依る（検証済み）。** `plugins: [lismCss({ purge: true }), viteSingleFile()]` なら CSS は 49,995 → 17,340 bytes に減って `<style>` に入り、今の `styles.css` の 100 のセレクタはすべて残った。`viteSingleFile()` を前に置くと purge は黙って効かなかった（全部が残る）。Purge はビルド出力の JS に完全な文字列で現れるクラスしか残さないので、`` `-p:${n}` `` のように組み立てる名前は消える（docs「対応範囲と制約」）。
- **保守とエージェント:** 1.0.0 は 2026-10-01 に出たばかりで、その直前の 0.27〜0.31（2026-09）は毎回のように破壊的変更（`lh`・`bdrs`・`bxsh` の値の変更、レイヤーの削除など）を含んだ。npm の週の DL は 1,813（Tailwind の約 7 万分の 1、Foldkit の約 15 分の 1）、GitHub の星は 332。公式がエージェント向けのスキル（`skills/lism-css-guide`）と MCP サーバー（`@lism-css/mcp`）を配っているが、Foldkit 側の手本（examples・同梱スキル）は Tailwind だけで、Lism CSS の言及は Foldkit・snabbdom のどちらのリポジトリにも無い。
- **推奨（決めるのは #772）:** 書き方を替えるなら、#748 の決定どおり Tailwind。Lism CSS は Foldkit と組めるが、(1) base が全要素の行間・見出し・色を変え、今の画面の寸法を保つには上書きが要る、(2) 1.0 が出たばかりで直前まで破壊的変更が続いた、(3) 利用と手本が Tailwind より桁違いに少ない、の 3 点で勧めない。Lism の良さ（レイアウトの部品・トークン）は、この画面（地図・字幕・右の列の固定配置）では使いどころが少ない。

## ビルド（Vite 8・1 ファイルの HTML）

- **素の CSS として読む（検証済み）:** 試作の `main.ts` に `import "lism-css/main.css";` を `../styles.css` の前に足し、キー一覧を `l--stack -g:5 -p:20 -bd -bdrs:10 -bgc:base -fz:s nopan`、行を `l--flex -g:10 -ai:center` に書き換えて `vite-plugin-singlefile` で build した。出力は `index.html` 1 つで `<link>` は無く、`<style>` 1 つ（49,398 bytes）に `@layer lism-base`・`.l--stack`・`.-p\:20`・`.map-node--blink`・`@keyframes map-node-blink` が入った。プラグインは要らない。
- **`@lism-css/plugin`（検証済み）:** peer は `vite: ^6 || ^7 || ^8`。`lismCss()` は `import 'lism-css/main.css'` を横取りして、`lism.config.js` を反映した CSS をその場で SCSS からコンパイルする（`documents/lism-config.md`「処理フロー」）。依存に `sass`・`postcss`・`cssnano`・`autoprefixer`・`glob`・`jiti` を持ち、pnpm で入れると `@parcel/watcher` のビルドスクリプトが承認待ちで止まった（ビルド自体は承認なしで通った）。設定ファイルは Vite の root から `lism.config.ts`→`.mjs`→`.js` の順に探す。
- **トークンの差し替え（検証済み）:** 試作の root に `lism.config.js` を置き、`tokens.color` に今の hex（`base: "#fff"`・`text: "#111827"`・`divider: "#e5e7eb"` など）を書くと、出力の `:root` がその値になった。
- **CSS Purge と single-file（検証済み）:** `plugins: [lismCss({ purge: { report: true } }), viteSingleFile()]` で build すると `[plugin lism-css:purge] CSS: 49995 → 17340 bytes (-65.3%)` と出て、残った CSS が `<style>` に入った。使ったクラス（`.l--stack`・`.-p\:20`・`.-fw\:bold`）は残り、使っていない `.l--grid`・`.-p\:30`・`.-bxsh\:20` は消えた。`h.Class("…")` の文字列はビルド出力の JS にそのまま残るので検出された。今の `styles.css` の 100 のセレクタはすべて残った（docs「ユーザー定義のクラスや他ライブラリの CSS は変更しない」のとおり）。順番を逆にして `[viteSingleFile(), lismCss({ purge })]` にすると purge は走らず、全部が残った（報告の行も出ない）。
- Purge の制約: 「ビルド出力の HTML / JS に完全な文字列として現れるクラスだけを検出できます」「SPA（Vite + Reactなど）: CSR領域のprops由来のクラスは自動検出できません」。Foldkit で `h.Class` に文字列の定数を書く限りは検出されるが、テンプレート文字列で組み立てた名前は `safelist` に書く必要がある（`ja/customize/purge.mdx`）。
- dev サーバー（HMR）での動きは **未検証**。

## 今の CSS との相性

### base が今の画面に与える影響（検証済み）

`main.css` を今の `styles.css` の前に読み、ノード・根拠の見出し・本文・リスト・キー一覧を同じ文で描いて、Chrome で寸法と `getComputedStyle` を比べた（`probe/current.html` と `probe/with-lism.html`）。

| 要素 | 今（`styles.css` だけ） | `main.css` を足したとき | 理由 |
|---|---|---|---|
| ノード（`.map-node`、2 行に折り返す文） | 高さ 76.8px | 96px | base の `* { line-height: var(--lh, calc(1em + var(--hl) * 2)) }` が `.map-node__text` の span にも当たり、`.map-node` の `line-height: 1.4` が継がれない |
| `.evidence h2` | 太さ 700、高さ 21px | 太さ 600、高さ 26px | base の `:is(h1,…,h6){font-weight: var(--fw--bold)}`（600）と行間 |
| `.evidence__text`・`li` | `line-height: normal`（24px・37px） | 28px・41px | 同じく `*` の行間 |
| `body` の文字色 | `#000` | `#141414` | base の `body { color: var(--text) }`。背景・字体は `styles.css` が書いているので変わらない |

- base は `@layer lism-base` の中にあり、層の外の `styles.css` が書いたプロパティは必ず勝つ（MDN `@layer`）。変わるのは `styles.css` が書いていないプロパティだけ。
- `main.css` の後に `@layer lism-base { * { line-height: inherit } :is(h1,h2,h3,h4,h5,h6),b,strong,dt { font-weight: bold } }` を足すと、ノード 76.8px・見出し 700・本文 normal に戻った（検証済み）。同じ層・同じ詳細度で後ろにあるので勝つ。ただし Lism の行間の仕組み（`--hl`・`-lh:*`）を使わない前提になる。
- base だけを外す正式な口は無い。`lism-css/reset.css`・`base.css`・`props.css`・`primitives/layout.css` は個別に import できる（`exports` の `./*.css`）が、`base.css` はトークンと要素のスタイルを 1 つのファイルに持ち、個別の CSS には `@layer` が付かない（`main.css` だけが層に包む）。SCSS（`lism-css/scss/*`）から組み直せば分けられるが **未検証**。
- 今の `styles.css` はボタン（`.map-node__button`・`.changes__button`・`.review-bar__button`）に `border: 0; background: none; font: inherit` を書いているので、base の `button { background-color: var(--base-2); border: 1px solid var(--divider) }` は効かない。`styles.css` が書いていない新しいボタンを足すと、灰色の地と枠が付く。

## 見た目の好み（既定の色・影・角丸）

- 既定の色は `--base: #fcfcfc`・`--text: #141414`・`--divider: #dfe0e2`・`--brand: #0f78f0` などで、今の 9 色（Tailwind v3 の gray）とは別の値。`lism.config.js` の `tokens.color` で今の hex に置き換えられる（検証済み）。プラグイン無しなら `:root` の CSS 変数を自分の CSS で上書きする手もある（base は層の中なので、層の外の `:root{--base:#fff}` が勝つ。**未検証**だが #747 と同じ層の規則による）。
- 影: `--bxsh--10`〜`50` は 2 層の影（v0.27.0 で変更）。`-bxsh:20` などを書かなければ付かない。base は要素に影を付けない（`base.css` に `box-shadow` は無い）。`tokens.bxsh: null` で影のトークンとクラスを出力から外せた（検証済み、docs に無い方法）。`color.shadow: "transparent"` で影の色を消すこともできる（検証済み）。
- 角丸: `--bdrs--10`（0.25rem）〜`99`。`-bdrs:*` を書かなければ付かない。base が角丸を付けるのは無い（`base.css` に `border-radius` は `.set--plain` の `0` だけ）。
- base が付ける見た目: 入力欄とボタンの灰色の地と 1px の枠、`blockquote` の地、`hr` の線、見出しの大きさ（`h2` は約 1.6em）。Tailwind の Preflight が「消す」方向なのに対し、Lism の base は「最初から整える」方向で、今の画面ではそれを打ち消す上書きが要る（上の節）。
- エージェントが Lism で書くと `-bxsh:*` などを足しやすいかは **未検証**。公式スキル（`skills/lism-css-guide`）は「アンチパターン」の資料を持つが、影を控えよという指示かは読んでいない。

## 推奨（#772 で決める）

1. **#748 の決定（Tailwind）を変える理由は見当たらない。** Lism CSS は Foldkit の `h.Class` にも 1 ファイルの HTML にも載り、技術的な壁は無い。ただし次の 3 点で Tailwind より不利。
   - **base が見た目を変える:** 全要素の行間・見出しの太さ・文字色が変わり、ノードの高さが 25% 伸びた。今の寸法を保つには `@layer lism-base` への上書きを持ち続ける必要がある。Tailwind は Preflight を import しないだけで外せる（#747）。
   - **安定の実績が短い:** 1.0.0 は 9 日前。直前の 1 か月に破壊的変更が 5 回あった。
   - **利用と手本が少ない:** 週の DL は約 1,800、Foldkit の手本・スキルは Tailwind だけ。
2. Lism の得意なところ（Every Layout 風のレイアウトの部品・余白と文字の段のトークン・コンテナクエリでのレスポンシブ）は、文書やサイトの組版向けで、地図・字幕・右の列を固定の寸法で並べるこの画面には合いにくい。
3. それでも Lism を選ぶなら: `main.css` を `styles.css` の前に読み、`@layer lism-base` で行間・見出しの太さを戻し、`lism.config.js` で色を今の hex に、影のトークンを消す。Purge を使うなら `lismCss({ purge })` を `viteSingleFile()` より前に置き、クラスは `h.Class` に完全な文字列で書く。点滅・子孫セレクタ・`color-mix`・動的な `transform` は CSS と `h.Style` に残す。
