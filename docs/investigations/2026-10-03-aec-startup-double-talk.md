# AEC3 の開始直後のダブルトークの調査（Issue #118）

`WebRTCEchoCanceller`（AEC3）が、開始直後に自分の声（ダブルトーク）を削っていないかを、合成音声で測った。結論は次のとおり。本番の挙動は変えていない（変更は `EchoCanceller` と `WebRTCEchoCanceller` などの `public` 化だけ）。実会議の録音は使っていない。

- **削られる。ただし、漏れの無い条件（参照は再生されるが、マイクには漏れない。イヤホン相当）の開始直後に限る。** 計画時の基準（開始 5 秒の発話の残り方が、30 秒・60 秒の両方より 3 dB 以上小さい）を、漏れ無しに当てはめると、5 秒は 30 秒より 4.82 dB、60 秒より 5.26 dB 小さい（−9.77 / −4.95 / −4.52 dB）。開始 1〜7 秒は、定常より 2.3〜9.5 dB 余計に削られ、10 秒には定常の値に戻った。原因は測っていない。
- **漏れ −10 dB（遅れ 40 / 200 / 300 ms）では、削られない。** 開始 5 秒の発話の残り方は、30 秒・60 秒と 0.7 dB 以内で同じだった。ただし、開始 1 秒・遅れ 40 ms だけ 3.7 dB 余計に削られた（200 / 300 ms は 0.6〜1.7 dB、2 秒以降は差が無い）。どちらも各条件 1 回の計測。
- 判定基準は計画時のものを漏れ無しにも当てはめた。初稿の限定の経緯は「判定基準」を参照。
- 直し方: **AEC3 の開始直後の状態を設定で変える方式**（初期の遅れの見積もり、`echo_canceller` の初期化の設定）を採用する。`bypass`（開始から N 秒は AEC の出力を使わない）は採用しない。測った bypass-3 / bypass-5 は 5 秒の発話の開始時には終了していて、5 秒の残り方を変えなかった（長い N は未測定）。一方、発話に重なる 2 秒・漏れ −10 dB では漏れの低下量が下がった（19.6 → 12.2 / 8.2 dB）ため。設定項目、値、効果は未測定で、実装 issue（#119）の受入条件で検証する。満たせなければ #119 の中で方式を見直す。

## 測り方

- 道具: `helper/Sources/stt-bench echo`（手順は `helper/README.md`）。台本は `helper/bench/scenarios/echo.json`（`meeting` は A の会議 10 行・約 125 秒、`self` は issue の 2 文）。声は `say`（A = Kyoko、B = Reed）。合成した音声と計測の出力は `/tmp/aec118` に置いた。リポジトリには入れていない。
- 入力: 会議の音（RMS −20 dBFS）を参照にして、`mic[i] = g * ref[i - d] + 発話` を作る。`g` は −10 dB、`d` は 40 / 200 / 300 ms（300 ms は issue の Bluetooth の上限）。発話は発話区間の RMS −20 dBFS にそろえ、最初の行の start が指定の秒（5 / 30 / 60）に来るように置く。
- 1 つの条件につき `WebRTCEchoCanceller` を 1 つだけ作り、10 ms ごとに reverse → capture を渡して、5・30・60 秒を 1 本の連続した流れとして処理する。
- 発話の残り方: AEC3 の出力は入力より 430 サンプル（約 9 ms）遅れるので、参照を無音にして雑音を通した出力から遅れを測り、その分だけ出力を進める。そのうえで、出力のうち元の発話と同じ向きの成分のエネルギーを、元の発話のエネルギーと比べる（dB）。0 なら全部残り、−6 なら振幅が半分になっている。窓は発話の長さ（約 11 秒、先頭の無音 1 秒と末尾 0.2 秒を含む）。STT の文字は測っていない（エネルギーを主とした。`--out` の wav を `stt-bench run` に通せば測れる）。
- 限界: 残り方は、出力（AEC3 が残した漏れを含む）を発話の向きへ射影している。漏れと発話は無相関の別の音なので、混ざる分は小さい前提で、AEC3 は非線形で成分を厳密に分離できない。漏れの無い対照を並べて、漏れ由来の差を確かめた。
- 漏れの低下量: 同じ窓で、マイクの信号と出力の、漏れの成分のエネルギーの比（dB）。
- 各条件 1 回の計測。同じ条件の繰り返しのばらつきは測っていない。代わりに、同じ条件（遅れ 200 ms、漏れ −10 dB）で発話の位置だけを 10〜100 秒の 9 か所に動かすと、残り方は −7.0〜−8.6 dB の範囲だった（参照の中身が位置ごとに違う影響を含む）。
- 純粋な部分（マイクの組み立て、連続処理、遅れの補正、dB の計算）は偽の canceller で `EchoBenchTests` に固定した。

## 判定基準

- **計画時の基準**（計測の前に決めた）: いずれかの遅れで、開始 5 秒の発話の残り方が、30 秒と 60 秒の両方より 3 dB 以上小さければ「削られる」。3 dB は設計判断。基準に、漏れの条件の限定は無い。漏れ無しの条件は、エコーと関係なく減る分を差し引く対照として、計画時に定義した。
- **この文書の初稿が付けた限定**: 初稿は、この基準を「漏れ −10 dB の条件」にだけ当てはめ、漏れ無しを基準の外とした。この限定は計画に無く、計測の前に決めたものではない。基準を後から変えたのではなく、基準を当てはめる条件を、初稿が誤って狭めていた。この文書では、計画時の基準を漏れ −10 dB と漏れ無しの両方に当てはめる。
- 当てはめ: 漏れ −10 dB は 3 つの遅れとも 0.7 dB 以内で、基準に届かない。漏れ無しは 5 秒が 30 秒より 4.82 dB、60 秒より 5.26 dB 小さく、基準を満たす（下の結果）。

## 結果

### 漏れ −10 dB（発話の残り方 dB / 漏れの低下量 dB）

| 遅れ | 5 秒 | 30 秒 | 60 秒 |
|---|---|---|---|
| 40 ms | −7.6 / 38.1 | −7.7 / 36.0 | −7.6 / 32.3 |
| 200 ms | −8.2 / 38.2 | −8.1 / 39.9 | −8.2 / 33.5 |
| 300 ms | −7.8 / 31.5 | −7.2 / 29.6 | −7.5 / 37.3 |

5 秒と 30 秒・60 秒の差は、最大 0.7 dB（遅れ 300 ms の 5 秒と 30 秒）。基準（3 dB）に届かない。5 秒の時点で、漏れは 31〜38 dB 下がっていて、収束している。

残り方が −7〜−8 dB なのは、開始直後の問題ではなく、全時刻で同じ値で出る（次の対照を参照）。

### 対照: 漏れ無し（参照は再生され、マイクには漏れない）

| 遅れ（結果は遅れによらず同じ） | 1 秒 | 2 秒 | 3 秒 | 5 秒 | 7 秒 | 10〜100 秒 |
|---|---|---|---|---|---|---|
| 発話の残り方（dB） | −10.0 | −14.1 | −12.0 | −9.8（−9.77） | −7.2 | −4.5〜−5.0（30 秒 −4.95、60 秒 −4.52） |

漏れが無いと、定常では −4.5〜−5.0 dB（高域通過フィルターなど、エコーと関係なく減る分を含む）。開始 1〜5 秒は、30 秒・60 秒の値（−4.95 / −4.52 dB）との差が、1 秒 5.1〜5.5、2 秒 9.1〜9.5、3 秒 7.1〜7.5、5 秒 4.8〜5.3 dB。7 秒で 2.3〜2.7 dB、10 秒で定常に戻る。参照が再生されているのに漏れが無い（イヤホンなど）状況で、開始直後の発話が削られることを示す。原因（AEC3 のどの機能か）は測っていない。

### 基準の外: 漏れ −10 dB で、開始 1〜3 秒（1 回ずつ）

| 遅れ | 1 秒 | 2 秒 | 3 秒 |
|---|---|---|---|
| 40 ms | −11.3 / 23.7 | −6.8 / 17.0 | −7.6 / 20.7 |
| 200 ms | −8.8 / 17.3 | −7.5 / 19.6 | −8.2 / 23.4 |
| 300 ms | −9.2 / 15.1 | −6.8 / 11.6 | −8.1 / 23.8 |

開始 1 秒の遅れ 40 ms は、定常（約 −7.6）より 3.7 dB 小さい。位置のばらつき（約 ±0.8 dB）より大きいが、1 回の計測で、2 秒以降は差が無い。漏れの低下量は 1〜3 秒で 12〜24 dB と、5 秒以降（30 dB 前後）より小さい。

## 結論

- **削られる。ただし、漏れの無い条件（イヤホン相当）の開始直後に限る。** 5 秒の発話は、30 秒より 4.82 dB、60 秒より 5.26 dB 小さく（−9.77 / −4.95 / −4.52 dB）、計画時の基準（3 dB 以上）を満たす。1〜7 秒も同様に定常より削られる（定常との差は、1 秒 5.1〜5.5、2 秒 9.1〜9.5、3 秒 7.1〜7.5、5 秒 4.8〜5.3、7 秒 2.3〜2.7 dB）。
- 漏れ −10 dB（遅れ 40 / 200 / 300 ms）の条件の、開始 5 秒の発話は、30 秒・60 秒と 0.7 dB 以内で同じ残り方で、削られない。ただし 1 秒・遅れ 40 ms だけは 3.7 dB 余計に削られた（1 回の計測。2 秒以降は差が無い）。
- 直し方は、記録済みの計測（`bypass` のみ測定）から、方式の水準で次のとおり決めた。
  - **採用: AEC3 の開始直後の状態を設定で変える方式**（初期の遅れの見積もり、`echo_canceller` の初期化の設定）。「候補の比較」の `bypass` が除外されるため、残る方式はこれだけ。効果は未測定。
  - **不採用: `bypass`**。根拠は、発話に重なる条件で測った漏れの低下量の悪化に限る。漏れ −10 dB・2 秒で、漏れの低下量が 19.6 から 12.2（bypass-3）/ 8.2（bypass-5）dB に下がる。5 秒・bypass-5 の 38.2 → 19.2 dB も同じ傾向だが、これは発話の開始に重ならない区間で漏れが戻った値。
  - 5 秒の結果の読み方: 漏れ無し・5 秒の残り方は baseline / bypass-3 / bypass-5 とも −9.8 dB で変わらなかった。ただし測った二つの設定は 5 秒の発話の開始時には終了しているので、これは「その二つでは改善しなかった」ことしか示さない。発話の区間まで続ける長い N の bypass は未測定で、5 秒の残り方を直せないとは言えない。
  - 漏れ −10 dB の 5 秒の発話は、もともと削られていない（0.7 dB 以内）。
  - 設定項目、値、効果は未測定。決定は未検証で、#119 の受入条件で検証する。満たせなければ #119 の中で方式を見直す（長い N の bypass を漏れの低下量の測定つきで比べることを含む）。

## 候補の比較

### 実施済み: `bypass`

`--candidate bypass-<秒>`（開始から N 秒は AEC の出力を使わず、AEC には通し続ける）を、遅れ 200 ms、1 回の計測で測った。発話の残り方（dB）/ 漏れの低下量（dB）。

| 発話の位置 | 条件 | baseline | bypass-3 | bypass-5 |
|---|---|---|---|---|
| 2 秒 | 漏れ −10 dB | −7.5 / 19.6 | −5.9 / 12.2 | −3.4 / 8.2 |
| 2 秒 | 漏れ無し | −14.1 / – | −8.2 / – | −3.7 / – |
| 5 秒 | 漏れ −10 dB | −8.2 / 38.2 | −8.2 / 38.2 | −8.2 / 19.2 |
| 5 秒 | 漏れ無し | −9.8 / – | −9.8 / – | −9.8 / – |

- 漏れ無しの 2 秒の残り方は、−14.1 から −8.2（bypass-3）/ −3.7（bypass-5）dB に戻る。
- 漏れ −10 dB の 2 秒の漏れの低下量は、19.6 から 12.2 / 8.2 dB に下がる。かけない区間では、発話が残る代わりに漏れが戻る。
- 5 秒の発話の残り方は変わらない（bypass-3 は 5 秒より前に終わる。bypass-5 は 5 秒の発話の開始に重ならない）。5 秒・漏れ −10 dB の漏れの低下量は、bypass-5 だけ 38.2 から 19.2 dB に下がる。
- 採用しない。根拠は、発話に重なる 2 秒・漏れ −10 dB で漏れの低下量が下がる測定（結論を参照）。5 秒の不変は測った二つの設定に限り、長い N は未測定。

### 採用: AEC3 の設定（効果は未測定）

- 初期の遅れの見積もりを与える、`echo_canceller` の初期化の設定を変える、の 2 つ。
- 未測定の理由: C シムの `apm_create`（`helper/Sources/CWebRTCAPM/apm.cpp:23-37`）が設定を固定していて、設定の口が無い。`EchoCanceller3Factory` が使えるかも、確認していない（未確認）。設定の口の追加、ビルド、再計測は、この調査の範囲外。
- 設定項目、値、効果は未測定。実装 issue #119 の受入条件で検証し、満たせなければ #119 の中で方式を見直す。

## 測れなかったもの

- STT の文字での比較（エネルギーを主とした）。
- 繰り返しによるばらつき、他の声・他の会議の音、遅れ 300 ms を超える条件、漏れの減衰が −10 dB 以外の条件（漏れ無しを除く）。
- 漏れ無しの条件で、開始直後に削られる原因（AEC3 のどの機能か）。
- AEC3 の設定（初期の遅れの見積もり、`echo_canceller` の初期化の設定）の項目、値、効果。すべて未測定。#119 の受入条件で検証する。
- Bluetooth の実機。合成音声での再現だけ。
- `pnpm typecheck`: この worktree には `node_modules` が無く（`spawn ENOENT`）、実行できなかった。
