# server と web の型検査・テストは Linux で動くか（Issue #218）

map #217（CI を並列化して 1 分未満で green にする）の調査。`server` と `web` の型検査・テストを ubuntu ランナーで流し、macOS と同じ結果になるか、何が要るかを確かめた。

## 結論

- **動く。コードの変更は要らない。** ubuntu-24.04（x64）・ubuntu-24.04-arm の両方で、`server` の typecheck（tsc 2 本）・`web` の typecheck・`server` の test（19 ファイル 386 件）・`web` の test（15 ファイル）がすべて通った。同じワークフローの macos-26 と件数・結果が同じ（3 回流して 3 回とも全ジョブ成功）。
- **Linux で変えるのはワークフローだけ。** ①ルートの `pnpm typecheck`（`pnpm -r`）は helper の `swift build` を含むので、`pnpm --filter @live-mindmap/server typecheck` と `pnpm --filter @live-mindmap/web typecheck` に分ける。②helper 用の準備（`setup-uv`・webrtc-apm のキャッシュとビルド・`swift test`）は TS のジョブに要らない。③`playwright install chromium` は `--with-deps` 無しで通った（ランナーのイメージに Chromium の依存が入っている）。
- **ただし、Linux に移しても server test は約 74 秒から縮まない。** 時間の大半は `server.test.ts` 1 ファイル（約 75 秒、51 件、実時間の待ちが多い）で、vitest はファイルの中を直列に走らせる。`--shard` はファイル単位で分けるので、この 1 ファイルが 1 分の下限になる。1 分を切るには、`server.test.ts` をテスト名（`-t`）で分けて別ジョブにする必要がある（最上位の describe 2 つで 約 44 秒 / 約 31 秒）。
- 型検査は ubuntu・macOS とも 1 秒前後（TypeScript 7 のネイティブ実装）。今の `pnpm typecheck` の 26〜43 秒は、ほぼ helper の `swift build`。

## 試し方

`research/ci-linux` ブランチに、このブランチの push でだけ動く使い捨てのワークフロー `.github/workflows/linux-probe.yml` を置き、GitHub のホストランナーで流した。手元（macOS）には Docker 等のコンテナ環境が無いので、ローカルの Linux では試していない。

- マトリクス: `ubuntu-24.04` / `ubuntu-24.04-arm` × `playwright install chromium`（plain）/ `--with-deps`、比較用に `macos-26`（plain）。計 5 ジョブ。
- 手順: `checkout` → `pnpm/action-setup` → `setup-node`（24、pnpm キャッシュ）→ `pnpm install --frozen-lockfile` → `playwright install chromium` → `server typecheck` → `web typecheck` → `server test`（JSON レポーターでファイル・テストごとの所要時間を取る）→ `web test`。
- 実行: [run 37443283089](https://github.com/daiki-beppu/live-mindmap/actions/runs/37443283089)、[run 37443646746](https://github.com/daiki-beppu/live-mindmap/actions/runs/37443646746)（遅いテストの一覧）、[run 37444112398](https://github.com/daiki-beppu/live-mindmap/actions/runs/37444112398)（describe ごとの合計）。どれも 5 ジョブすべて成功。

## macOS 依存の洗い出し

| 候補 | 実際 | Linux で要るもの |
|---|---|---|
| ヘルパーのバイナリ（`helper/.build/debug/live-mindmap-helper`） | 参照するのは `server/src/server.ts` の `import.meta.main` の中（本番起動）だけ。テストは `fixtures/fake-helper.ts` を `process.execPath`（node）で起動する（`server/test/server.test.ts` の `helper: { command: process.execPath, args: [fakeHelper, ...] }`） | 無し |
| `helper/.build`・swift | `server` の `dev` スクリプトだけが `swift build` を呼ぶ。`test`・`typecheck` は呼ばない | 無し（ルートの `pnpm -r typecheck` を使わない） |
| OS コマンド・パス | テストは `os.tmpdir()` と `mkdtemp` で一時フォルダを作る。シグナル（SIGTERM / SIGKILL）は POSIX 共通で、Linux でも同じ時間で通った | 無し |
| Playwright の Chromium（`capture.test.ts`、`server.test.ts` の map.png） | `--with-deps` 無しでも通った。ubuntu-24.04 の plain では日本語フォント（`fc-list :lang=ja`）が 0 件だが、テストは DOM の位置・本文・PNG のシグネチャと寸法を見るので影響しない。`--with-deps` だと IPA ゴシック等が入り、+13〜21 秒 | `playwright install chromium`（plain で可） |
| pnpm の lockfile | `@pnpm/exe.linux-*` 等、Linux 用の任意依存も lockfile に載っている | 無し |
| テストの出力の `ENOENT ... 相手.m4a` | macOS でも同じ 2 行が出る（テストは成功）。Linux 固有ではない | 無し |

## 試作で使うこと

- TS のジョブは `runs-on: ubuntu-24.04`（arm でも同じ結果・同じ速さ）。helper の準備を外し、`pnpm --filter` で server / web を個別に流す。
- `playwright install chromium` は `--with-deps` 無しで足りる（今のイメージでは）。キャッシュするなら `~/.cache/ms-playwright` を playwright のバージョンをキーにして。
- server test の分割は `--shard` では 1 分を切れない（vitest 5.0.3 の `--shard` はテストファイルを分ける。ファイル数より大きい count はエラーになる: `--shard <count> must be a smaller than count of test files`）。`server.test.ts` だけを `-t` で分けて別ジョブにし、残りのファイルは `--exclude test/server.test.ts`（または `--shard`）で流す形が候補:
  - `vitest run test/server.test.ts -t "ライブのセッション"`（約 43 秒）
  - `vitest run test/server.test.ts -t "ヘルパーが予期せず終わった"`（約 31 秒）
  - `vitest run --exclude test/server.test.ts`（最長は `eval.test.ts` の 33〜42 秒）
  - `-t` の分け方が実際に通るかは試作で確かめる（この調査では流していない）。テスト名にどちらにも当たらないものが出ないよう、件数（51 件）を合わせて確かめる。
- これで最長のジョブのテストは 45 秒前後になり、セットアップ 20 秒を足すと 1 分すれすれ。余裕を作るなら「ライブのセッション」をさらに分ける（例: 「録音」の describe を別に）。

## 遅いテスト（map の範囲外、記録として）

ubuntu-24.04 plain の上位（run 37443646746）。いずれも実時間の待ちを含み、macOS でもほぼ同じ時間。

- 10.5 秒 `server.test.ts` ライブのセッション「ヘルパーが SIGTERM で終わらなくても、stop は時間内に戻り…SIGKILL に切り替えた…」（`HELPER_STOP_TIMEOUT_MS` 5 秒を実時間で 2 回待つ）
- 6.1 秒 同 Issue #161「起動し直した後に SIGTERM で終わらないヘルパーを SIGKILL で止めると…」
- 5.2 秒 同「ヘルパーが SIGTERM で終わらなくても、サーバーの close は時間内に戻り…」
- 5.0 秒 `capture.test.ts`「全体を下限の倍率でも収められない大きさなら…」（ubuntu だけ遅い。macOS は 1.4 秒）
- `eval.test.ts` は 47 件で合計約 40 秒。1 件 1〜4 秒で、`play` を実際に流す（`runCli(["play", ...])`）ものが多い。
