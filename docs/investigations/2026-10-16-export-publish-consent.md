# 他人の発言・録音を会議の後に外へ出すときの、同意と権利の実務（Issue #1208）

地図 [#1206](https://github.com/daiki-beppu/live-mindmap/issues/1206)（エクスポートの公開）の調査チケット [#1208](https://github.com/daiki-beppu/live-mindmap/issues/1208)。会議の後に、他人の発言（要約のマップ・発言の文字・録音）を URL で外に出すときの同意と権利を、一次資料で調べた。日本の法は e-Gov の条文（著作権法・個人情報保護法）、文化庁「著作権テキスト（令和8年度）」、個人情報保護委員会（PPC）の「ガイドラインに関する Q&A」で、他の会議 AI ツールは各社の公式ヘルプで確かめた。調べた日は 2026-10-16。

**これは法的な助言ではない。** 製品の既定値と、利用者への確認の出し方を決める材料としてまとめた。条文から読み取った解釈には「（解釈）」、一次資料で裏が取れていないものには **［未確認］** と付けた。

## 結論

- **録音の配布は、発言の文字やマップより一段重い。** 講演は「言語の著作物」で、原稿なしの講演も守られる [2][3]。生の講演を録音・筆記するのは複製に当たる [3]。URL で誰でも聞ける状態に置くのは公衆送信（送信可能化を含む）に当たる [1]。さらに音声は、話し手を特定できれば個人情報になる [5]。録音を既定で出さないという地図の決定は、法の重さの順と合っている
- **発言の文字（字幕）も、講演や創作的な発言を逐語で写した物なので、録音と同じく複製・公衆送信の対象になりうる。** 「単なる事実やデータ」「ありふれたもの」は著作物ではない [3] ので、雑談や短い受け答えまで著作物とは限らない。とはいえ、どの発言が著作物かを製品が切り分けることはできない。発言の文字を既定で出さない決定は妥当（解釈）
- **要約のマップは、言い回しをどれだけ残すかで扱いが変わる。** 思想・アイデアや事実そのものは守られない [3] ので、論点や結論を抜き出した物は権利が働きにくい。一方、創作的な表現を残した要約は翻案（第27条）や同一性保持（第20条）の問題になりうる [1]（解釈）。マップを既定の中身にするのは、3 つの中で最も軽い選択
- **社内の会議・社外の会議・公開のイベントで違うのは、主に「公表済みか」と「相手が誰か」。**
  - 公開のイベントの講演は、登壇者が公衆に口述しているので「公表された著作物」になる（第4条）[1]。公表済みなら引用（第32条）の余地が出るが、引用は「公正な慣行」と「正当な範囲」が条件で [1]、講演の録音や全文をそのまま載せる形はこれに当たりにくい（解釈）
  - 社内・社外の閉じた会議の発言は未公表のまま。未公表の著作物を公衆に出すかどうかは著作者が決める（公表権、第18条）[1]
  - 著作権法の「公衆」は「不特定の者」と「特定かつ多数の者」を含み、特定かつ少数の者だけが公衆でない [3]。**URL を知る誰でも見られる公開は公衆向け**。メールで限った少数の相手だけに見せるなら公衆向けでないと評価できる余地がある（解釈）
  - 政治上の演説・裁判の公開の陳述などは自由に使える（第40条）が、技術イベントの講演や会議は対象外 [1]
- **個人情報保護法は、使う人が「個人情報取扱事業者」で、出す物が「個人データ」のときに同意（第27条）が要る。** 録音した会話は、氏名で容易に検索できるよう整理されていなければ個人情報データベース等に当たらない [5]。会議 1 本のマップ・字幕・録音は、そのままなら個人データでない可能性が高い（解釈）。ただし個人情報には当たるので、事業として扱うなら利用目的の特定・通知または公表（第17条・第21条）は要る [4]。営利・非営利を問わず、反復継続する活動なら「事業」に当たる [5]。公開情報でも個人情報であることは変わらない [5]
- **Cloudflare に置くこと自体は、Cloudflare が中身を扱わない契約なら「提供」に当たらない**（PPC Q&A 7-53、10-25、12-3）[5]。問題になるのは置き場ではなく、URL を渡す先（閲覧する人）の方
- **イベントの主催者の規約は、参加者と主催者の間の約束。** 録音・録画・SNS 投稿を禁じる主催者は多い [10]。connpass の利用規約自体は録音に触れておらず、個々のイベントの決まりは主催者に任せている [9]。登壇者が主催者に配信を許していても、それは主催者への許諾で、参加者が録音を配り直してよいことにはならない（解釈）。製品はイベントの規約を読めないので、利用者に確かめさせる形になる
- **他の会議 AI ツールの既定は「会議の参加者（招待者）に共有」寄りと「本人だけ」寄りに分かれる。** URL を知る誰でも見られる形を既定にしているのは Fireflies だけで、他は招待者・社内・本人に絞るか、利用者が選ぶ。期限は Fireflies（パスワード付きリンク、有料プラン）と Zoom（クラウド録画の共有）が持つ。通知は、参加者として見える bot・会議のチャットへの投稿・事前のメール・画面上の印で出し、tl;dv と Otter（Teams）は明示の同意を取る仕組みも持つ
- **要約と、発言の文字・録音とを分けて扱う例はある。** Zoom はクラウド録画の共有で「閲覧者が文字起こしを見られる」を別のスイッチにしている [13]。AI Companion の要約も、録画・文字起こしとは別に共有する [12]。Notion は Enterprise で文字起こしを自動で消しても要約とメモを残せる [17]。Google Meet の Gemini のメモは録画・文字起こしとは別の機能で、録画とは別に共有先を選ぶ [14][15]。一方、Otter・Fireflies・tl;dv は共有の単位が会議ごとで、要約だけを出す選択肢は公式ヘルプに見当たらない（tl;dv はリンクに「メモを含めるか」だけ選べる）

## 製品の既定値と確認への材料

上の事実から読める、エクスポートの公開の既定値の候補（地図で決める材料として）。

| 中身 | 法の重さ（解釈） | 他ツールの扱い | 既定値の候補 |
|---|---|---|---|
| マップ（要約） | アイデア・事実が中心なら権利は働きにくい。言い回しが残ると翻案・同一性保持の問題 | Zoom・Google Meet・Notion は要約を録画・文字起こしと別に扱う | 既定で出す。公開の前に「相手の発言の要約を外に出す」ことを 1 度確かめる |
| 発言の文字（字幕） | 逐語の写しなので、講演や創作的な発言なら複製・公衆送信。話し手を特定できれば個人情報 | Zoom は録画の共有で文字起こしの表示を別スイッチにしている | 既定では出さない。選ぶときは「相手の話そのもの」と明示し、閉じた会議なら相手の了解を取ったかを確かめる |
| 録音 | 複製・公衆送信に加えて、声は個人情報。実演に当たる場合は実演家の録音権・送信可能化権も［未確認］ | どのツールも録音は会議の参加者・社内への共有が中心。Zoom・Fireflies に期限 | 既定では出さない。選ぶときは、登壇者・参加者の許可を得たことを利用者が明示する |

見せる相手については、「URL を知る誰でも」は著作権法の「公衆」向けに当たり、個人データなら第三者提供の同意が要る形になる [3][5]。閲覧の共有（仕様 #805）と同じく、メールで絞る形を既定にし、誰でも見られる形は明示の選択にするのが、法の線と他ツールの既定の両方に合う（解釈）。

## 日本の法の観点

### 著作権法

| 論点 | 条文・資料 | 要点 |
|---|---|---|
| 講演は著作物か | 第10条第1項第1号 [1]、テキスト「一般の著作物」[3] | 「講演」は言語の著作物の例示。固定は要らないので「原稿なしの講演」も守られる |
| 何が著作物でないか | 第2条第1項第1号 [1]、テキスト [3] | 「単なる事実やデータ」「ありふれたもの」「アイデア」は除かれる。事実の伝達にすぎない雑報・時事の報道も除かれる（第10条第2項） |
| 口述権 | 第24条、第2条第1項第18号 [1]、テキスト「口述権」[3] | 言語の著作物を公に口述する権利。口述は「朗読その他の方法により著作物を口頭で伝達すること（実演に該当するものを除く。）」。録音した講演を再生して聞かせるのも口述に含まれる。ただし URL での配信は口述ではなく公衆送信の方で扱う |
| 録音・筆記 | 第21条 [1]、テキスト「複製権」[3] | 「『生』の講演を録音、筆記したり」する行為に複製権が働く。発言の文字・録音はどちらも複製 |
| URL での公開 | 第23条、第2条第1項第9号の5 [1]、テキスト「公衆送信権」「公衆とは」[3] | 公衆送信（送信可能化を含む）の権利。「公衆」は不特定の者と特定かつ多数の者 |
| 要約 | 第27条、第20条 [1] | 翻案する権利と、意に反する改変を受けない権利。要約がどこから翻案に当たるかは条文に線が無い **［未確認］**（判例の確認はしていない） |
| 公表済みか | 第4条、第18条 [1] | 公衆に口述された講演は公表されたものになる。閉じた会議の発言は未公表で、公表は著作者が決める |
| 自由に使える場合 | 第30条、第32条、第40条、第41条 [1] | 私的使用の複製は「個人的に又は家庭内その他これに準ずる限られた範囲内」に限られ、URL での公開は含まない。引用は公表済みの著作物だけ。第40条は政治上の演説・裁判手続などに限る。第41条は時事の事件の報道のため |
| 実演家の権利 | 第2条第1項第3号、第91条、第92条の2 [1] | 実演家は録音権・送信可能化権を持つ。自作の講演を話すことが「口演」として実演に当たるのか、口述に当たるのかは条文から決めきれない **［未確認］** |

### 個人情報保護法

| 論点 | 条文・資料 | 要点 |
|---|---|---|
| 発言・声は個人情報か | 第2条第1項 [4]、Q&A 1-10・1-11 [5] | 「音声、動作その他の方法を用いて表された」記述で特定の個人を識別できれば個人情報。通話の録音も話し手を特定できれば個人情報 |
| 会議の録音・文字は個人データか | 第16条 [4]、Q&A 1-41・1-42 [5] | 「録音した会話の内容に…氏名が含まれていても、当該氏名により容易に検索可能な状態に整理されていない限り」個人情報データベース等に当たらない。映像も体系的に構成していなければ当たらない |
| 誰が義務を負うか | 第16条第2項 [4]、Q&A 1-50・1-54 [5] | 個人情報データベース等を事業の用に供している者。営利・非営利を問わず、扱う人数の多寡も問わない |
| 第三者に見せる | 第27条第1項・第5項 [4]、Q&A 1-49 [5] | 個人データの第三者提供には原則として本人の同意。公開情報から作った検索可能なデータベースを不特定多数が見られる状態にするのも第三者提供に当たる。委託に伴う提供は第三者提供に当たらない |
| 外の置き場 | 第28条 [4]、Q&A 7-53・7-54・10-25・12-3・12-4 [5] | クラウド事業者が個人データを扱わない契約なら「提供」に当たらず、本人の同意は要らない（外国の事業者でも同じ）。ただし利用者自身の安全管理措置は要る。事業者が中身を扱うなら外国にある第三者への提供になりうる。Cloudflare Pages の契約上の扱いは **［未確認］** |
| 利用目的 | 第17条・第21条 [4] | 個人情報を扱うなら利用目的をできる限り特定し、取得したら通知または公表。取得の状況から利用目的が明らかなら不要（第21条第4項第4号） |
| 適用除外 | 第57条 [4] | 報道機関・著述を業とする者などが報道・著述の目的で扱う場合は義務の章が適用されない |

### 社内・社外・公開のイベントの違い（解釈）

| 場面 | 著作権 | 個人情報 |
|---|---|---|
| 社内の会議 | 発言は未公表。業務上の発言の著作権が会社に帰属するか（職務著作、第15条）は個別の事情による **［未確認］** | 社内でも話し手を特定できれば個人情報。会社が個人情報取扱事業者なら、社外に見せることは社内の規程・利用目的の範囲の問題 |
| 社外との会議 | 相手の発言は相手（またはその会社）の物で、未公表 | 相手の発言・声は個人情報。事業として扱うなら利用目的の通知等が要る |
| 公開のイベント | 講演は公表済み。それでも録音・全文の配布は複製・公衆送信で、許諾か引用の範囲が要る | 登壇者の発言も個人情報。公開されていても個人情報であることは変わらない [5] |

なお、肖像権・プライバシー権・パブリシティ権は条文に無く判例で認められてきた権利で、今回は一次資料（判決）を確かめていない **［未確認］**。会話の録音の取得そのものの適否も、このチケットの範囲外とした。

## 公開イベントの規約・方針

- 主催者の規約は、主催者と参加者の間の約束。調べた主催者の多くは、録音・録画・配信内容の再利用や SNS への投稿を禁じている（例: 埼玉県のオンラインイベントの規約は「配信内容の撮影、録画、録音、複製及び再利用を行わないこと」）[10]
- connpass の利用規約は録音・撮影に触れず、参加者からの問い合わせは主催者が「責任を持って対応する」としている [9]。決まりはイベントごとの案内（イベントページ）にある
- 今回の発端の Findy のイベント（AI-DLC）の規約・撮影の方針は確かめていない **［未確認］**
- 主催者が配信やアーカイブを公開していても、それは登壇者と主催者の間の許諾で、参加者が自分の録音を配り直す根拠にはならない（解釈）。主催者が「撮影・録音・SNS 可」としていれば、参加者の録音や投稿の範囲が広がる。その範囲は規約の書き方次第
- 製品の側から言えることは、利用者に「イベントの規約で録音や再配布が許されているか」を確かめさせる以上のことは無い（解釈）

要約と、発言の文字・録音とを分けている例:

- Zoom: 要約（AI Companion）と文字起こし・録画が別の出力で、録画の共有では文字起こしの表示を別のスイッチにしている [12][13]
- Google Meet: Gemini のメモは録画・文字起こしとは別の機能で、共有先も別に決まる [14][15]
- Notion: 文字起こしを自動で消して要約とメモを残す設定がある（Enterprise）[17]
- tl;dv: 録画のリンクにメモを含めるかを選べる（要約を外す方向）[19]
- Otter・Fireflies: 共有の単位は会議ごと。要約だけを出す選択肢は公式ヘルプに見当たらない [6][11][16]
