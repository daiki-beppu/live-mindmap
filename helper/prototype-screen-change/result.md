# 共有画面の「中身が変わった」の判定（試作の結果、issue #252）

使い捨て。`scenario.html`（会議アプリ風の台本ページ、166 秒）を別の Chrome で開き、`record.swift` でそのウィンドウを 4 fps で取り込み、`detector.js` の判定を `viewer.html` で当てて見た。

## 動かし方

```sh
swiftc -O record.swift -o /tmp/record
node run.mjs /tmp/record <出力先>   # 約 3 分。146 秒に別のタブ、156 秒に戻す
node build.mjs <出力先>             # <出力先>/index.html を開く
```

## 分かったこと

- Chrome のウィンドウは描き直し続けるので、`SCFrameStatus.idle` は 1 枚も出ず、`dirtyRects` は常にウィンドウ全体だった。判定は自前の画像比較が前提
- 前のフレームとの差では、ゆっくり動く顔の小窓が積み上がって 2〜3 秒ごとに送ってしまう。比べる相手は最後に送った画面に固定する
- 64×36 では、表のセル（1,580 → 1,620）の書き換えが差にならない。128×72（1280 幅で 1 マス約 10px）で拾えた
- 文字 1 行の追加はウィンドウの約 1%。顔の縁の揺れも約 1% で、しきい値だけでは分けられない。動いている場所を外して比べる必要がある
- 話している人の枠の移動は、送った画面の 1 枚と「そろって同じ」かで抑えられる（マスごとにどれか 1 枚と同じ、では甘く、数字の書き換えまで抑えてしまった）。最初の一巡（4 人なら 3〜4 枚）は送る
- 取り込みの開始が 1 回だけ「画面収録の TCC を拒否」で失敗し、再実行で通った（確認のダイアログは見当たらず、原因は未確認）

## 既定の値での結果（128×72）

送ってほしい 17 件のうち 16 件、余計 6 件（枠の最初の一巡 3、スクロールの途中 2、動画の縁 1）。漏れの 1 件は、2 回目のスクロールが止まったときの映り始めの時刻が 1.5 秒早く出たもの（送ってはいる）。
