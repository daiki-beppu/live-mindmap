# PROTOTYPE: 差分更新エンジン

使い捨ての試作。本番コードではない。[差分更新エンジン：操作スキーマ・プロンプト・更新タイミング](https://github.com/daiki-beppu/live-mindmap/issues/6) の問いに答えるために作った。

## 問い

録音サンプルの文字起こしを会議の時間順に再生し、Claude が既存のマップに差分操作（追加・更新・統合・移動・削除・何もしない）を出したとき、

- 操作スキーマはどんな形がよいか
- 何発言ごとに呼び、1 回にどんな文脈を渡すか
- 同じ話題に戻ったとき、既存ノードに続きを足せるか
- 60 分の会議でコストと遅延が許容範囲に収まるか

あわせて、System One モデル（Jev）を Claude の前段ゲートに置く案も試した。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `map.ts` | マップと差分操作の純粋モジュール。`CONTEXT.md` の規則で操作を検証して適用する。本実装に持ち上げられる部分 |
| `claude.ts` | プロンプト（v3）と操作スキーマ。Agent SDK（サブスク）経由で Claude を呼ぶ |
| `gate.ts` | Jev ゲートのアダプタと判断方針（v1 の質問設計） |
| `run.ts` | 文字起こしを再生して、呼び出しごとの操作・マップ・トークン・概算費用・遅延を JSON に残す |
| `eval-gate.ts` / `eval-gate2.ts` | Jev ゲート単体の評価（v1 の質問設計 / 会議の目的とマップを渡し役割を選ばせる v2） |
| `viewer.html` / `bundle.ts` | ラン JSON を時間スライダーで見るビューア。`bun bundle.ts` で埋め込み済みの `report.html` を作る |

## 動かし方

```sh
bun install
bun run.ts --sample facilitators-meeting --model claude-sonnet-5-5 --batch 2   # Claude のみ
bun run run -- --gate jev                                                       # Jev ゲートあり（op run で .env.op を解決）
op run --env-file=.env.op -- bun eval-gate2.ts                                  # ゲート単体の評価
bun bundle.ts && open report.html
```

- 入力は `~/live-mindmap-samples/*.transcript.json`（[回帰評価用の会議録音サンプルを用意する](https://github.com/daiki-beppu/live-mindmap/issues/4)）
- ラン結果（`runs/`・`report.html`）は文字起こし全文を含むので git に入れない。この試作で作ったものは `~/live-mindmap-samples/diff-engine-runs/` にある
- Claude はサブスク経由（Agent SDK）で呼ぶ。概算費用は SDK が API の定価で見積もった値で、請求額ではない
- Jev のキーは 1Password にあり、`.env.op` の参照を `op run` が解決する

## 結果（Sonnet 5.5、2 発言ごと、60 分）

| | ノード | 本文 p90 / 最大 | 深さ | 決定 / TODO | 概算費用 | 応答 p50 |
| --- | --- | --- | --- | --- | --- | --- |
| ファシリテーター v1 | 52 | 119 / 427 字 | 5 | 4 / 1 | $1.85 | 3.1 秒 |
| ファシリテーター v2 | 103 | 33 / 42 字 | 9 | 2 / 0 | $1.91 | 3.3 秒 |
| ファシリテーター v3 | 38 | 37 / 45 字 | 4 | 3 / 1 | $1.39 | – |
| ブレスト v3 | 58 | 37 / 50 字 | 3 | – | $1.61 | – |

- v1: 「続きは update で表す」を本文への追記と読み、ノードが肥大化した
- v2: 本文を 40 字に制限し続きを子ノードにしたら、ノードが倍増して深くなり、決定と TODO が案に化けた
- v3: 子にするのは別の主張のときだけ、言い換えは根拠を足す update、毎回「経過・ノード数・深さ・目安」を添える。粒度と決定・TODO の拾い方が安定した
- 組み替え（move / merge）は v2・v3 とも一度も使われなかった
- 不正な操作は、ゲートのバグ由来を除き約 800 回の呼び出しで 2 件（空のマップで存在しない親を指定）
- Haiku 4.5 は構造化出力の再試行で 1 回 40〜70 秒かかり、Sonnet より高くなったので途中で止めた
- Jev ゲート: 文面だけで「中身があるか」を聞く v1 の質問設計では、ブレストのアイデアを 45% 取りこぼした。会議の目的とマップを渡して役割を選ばせる v2 では、「進行・雑談 かつ どのノードにも関係しない」で発言の 14〜18% を捨て、取りこぼしは 1〜2%。費用は 60 分で約 $0.05
